Block 5 · Results

Results: the LABG Report

Every analysis worth keeping goes to the report, where it joins the others in order, with tables and figures numbered consecutively, its assumptions, a paragraph for your thesis or paper, the technical details and the R code. The report does not store fixed results: it stores the requests, and it is recalculated with whatever data are there, so correcting a value corrects the whole report.

5.1Adding to the report

In Explore and in Analysis, every result has in its header, to the right of ⓘ What is this analysis?, the Add to report button. When you click it, a notice confirms how many analyses the report holds (“Added to the report (3 in total). See it in the Results block.”) and the button changes to In the report ✓; if you click it again, it takes you to the Results block instead of adding the analysis twice.

What gets added is the request: the method, the variables with their roles, and the options. If you then change an option (another comparison test, another confidence level), that is a different request: the button says Add to report again and, if you click it, both stay in the report.

When the report is empty, the block offers to take you to Analysis or Explore, or to Open a .labg project: a saved project brings the data and the complete report (section 7.6).

5.2The header and the index

  • Report title and Author or authors: they go on the cover of the exported document. The browser remembers the author for your next report.
  • The summary: how many analyses, tables and figures the report has and which data they come from (and how many analyses could not be computed, if there are any).
  • Copy all paragraphs (section 5.4), See the figures (chapter 6), Present and Export (chapter 7). Present shows the whole report as full-screen slides, one analysis after another, with its name in the top bar, so you can present it at a meeting or at a thesis defense (section 4.5).
  • The level of detail (section 4.5): in Basic, each analysis shows the reading of its tables instead of the tables and hides the technical details and the R code; in Expert, it opens them. The exported document is the same at all three levels.
  • The index: a link to each analysis, with its number.

5.3Each analysis in the report

Each analysis takes up a card with its number and its title (the method and the response: “Randomized complete blocks · rend”). The bar on the right has four buttons:

ActionWhat it does
↑ and ↓Move the analysis up or down in the report; the tables and figures are renumbered.
Open in AnalysisFor analyses that come from the Analysis block: takes the request to that block with its variables and its options and computes it again, so you can review or change it. Anything you change there is a new request: you add it to the report and remove the earlier one if it is no longer useful.
Open in ExploreFor summaries that come from Explore, the same button takes you to that block, but it does not put the variables back: a notice reminds you that the summary is adjusted there and added again.
RemoveTakes it out of the report. Ctrl+Z does not bring it back: you add it again from its block.

Below the bar, Title and note expands so you can change the title under which the analysis appears in the report (the suggested one stays as a guide, in gray) and write a note, which goes in the technical details: where the data came from, what was removed, what was decided and why.

Then comes the same content as in the source block, in this order:

  • In a nutshell (in analyses from the Analysis block) and the conclusion (section 4.5).
  • The tables, each with its Copy table button carrying its number (Copy table 1, Copy table 2…), which copies it tab-separated so you can paste it into a spreadsheet or into a table in a word processor. Download as CSV is not in the report: that button is in the result in Analysis or Explore (section 4.5), and the spreadsheet of chapter 7 contains every table with all its digits. Below each table, collapsed, is How to read this table (section 4.5): it is an on-screen aid; in its place, the exported document has a panel with gauges for the key statistics of each analysis (section 7.2).
  • The figures, also numbered consecutively, with the Chart theme selector above them. It is the same one as in Analysis: it changes the theme of every chart in the app.
  • The Assumptions: the analysis’s traffic light, if it has one (section 4.5), with the What to do box and its recommendation. Completely randomized and randomized complete block designs have no traffic light in Analysis; in the report, SigmaPro checks the assumptions of the same model on its own (normality of residuals, equal variances among treatments, block × treatment additivity in block designs, independence of residuals, and outliers) and adds its traffic light. With the maize data, all five lights are green and What to do says: “The assumptions are reasonably met: the analysis of variance and the mean comparisons will be reliable.”
  • For your thesis or paper, with How to report it (APA) collapsed at the end (section 5.4), and, collapsed, the Technical details and the Equivalent R code (section 5.5).

5.4The paragraph for your thesis or paper

In the For your thesis or paper section, each analysis has a Methods paragraph and a Results paragraph, written with its numbers and with the citation for the method when there is one. They are a starting point: the app says so next to the button, and you should review the wording and add the agronomic interpretation.

Copy the paragraph copies the two paragraphs of one analysis. Copy all paragraphs, in the header, gathers those of the whole report into one text with two sections: Methods, with the paragraph of each analysis and, at the end, a sentence that cites SigmaPro and R with their versions and the number of validation cases (if any analysis ran in the R engine, another sentence says so, with the version of R used inside the browser); and Results, with the paragraph of each analysis, numbered. With the maize data, the results of the first two analyses read as follows:

✎Results (text copied from SigmaPro)

1. The effect of bloque was significant (F(3, 33) = 10.40; p < 0.001); the effect of hibrido was significant (F(2, 33) = 60.63; p < 0.001); the effect of dosis was significant (F(3, 33) = 292.15; p < 0.001); the hibrido × dosis interaction was not significant (F(6, 33) = 1.47; p = 0.220). The grand mean was 5.938, with a coefficient of variation of 3.6 % and R² = 0.969.

2. The means, from highest to lowest, were H-66 (6.359 a), H-52 (5.922 b) and H-40 (5.533 c); means sharing a letter do not differ.

The paragraphs use the column names exactly as they are in the table (“rend”, “hibrido”): replace them with the full names when you paste them, or give the columns clear names in the Data block (section 2.7). The references cited in the paragraphs appear in full in the exported report.

The paragraphs, like the tables, come out in the language of the interface: with the selector set to ES (section I.5) they are written and copied in Spanish, with the same numbers.

Below the button, How to report it (APA) gives the same two paragraphs with APA 7 conventions (italics, p without a leading zero, intervals in square brackets) and in both languages, without changing the app’s language (section 4.5). In APA style, the first maize result begins: “The effect of bloque was significant (F(3, 33) = 10.40, p < .001)”.

5.5Technical details and R code

At the end of each analysis, two collapsed sections hold what another person needs to repeat it.

The Technical details (figure 5.3) give the method with its internal name; the inputs (which column played each role); all the options, including those left as they came; the data (their source, the number of rows and the filter, if there was one); the rows that actually entered the computation; the software: the SigmaPro version, how many validation cases against R the app has and how many of them belong to that method (if it ran in the R engine, the versions of webR, R and its packages); the computation time; and the note, if one was written.

The Equivalent R code is the same as in section 4.5: a script that, with the exported data, gives the same numbers in R. Copy the code copies it. The .labg project (section 7.6) gathers the code of the whole report into a single script, together with the data.

5.6A living report

Because the report stores requests and not results, each analysis is computed with the current data every time it is displayed or exported.

  • If you correct a value in the worksheet, add a row or turn on a filter (section 2.10), every analysis in the report is recalculated, and the technical details state the filter it was computed with.
  • If an analysis can no longer be computed (a column it used was deleted or renamed), its card says so with the box from section 4.5: what happened and what to do. The summary in the header counts it, and the others are unaffected. When the column comes back, so does the analysis.
  • Analyses in the R engine show “Computing in the R engine…” while they run; the export waits for them.
iClosing does not lose the report

The report, with the data, is saved automatically in the browser while you work (section 7.7), and you can save it in a .labg project to take it to another computer or share it (section 7.6).
